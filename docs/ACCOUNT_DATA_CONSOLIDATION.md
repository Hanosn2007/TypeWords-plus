## 已确定的产品约束

- 收敛为 TypeWords Plus 自己的数据体系，最终退役上游旧账号和 Supabase 常驻同步；不能止于隐藏界面。这是对上轮“暂留旧代码”的范围推进，不追溯认为已经完成退役。
- 云端默认保留最近3个有效日期；本机可设置保留天数，上限30个有效日期。有效日期不是最近3/30次操作，也不是距今天3/30个自然日。
- 本机和云端都能手动删除指定历史副本，列表明确来源、日期和内容摘要；删除历史不修改当前学习进度，不默认联动另一端。
- 本地优先，失焦/隐藏和手动触发同步；冲突人工比较处理。不得增加每几秒同步、逐键全量备份或同步失败后自动切换到旧服务。
- 保持本站账号ID、会话、词书/单元ID、共享词库固定版本、完整FSRS卡片、统计与完成标记、v3正式/自由任务及未归属旧任务。
- 词书内容导入与公共词书发布历史继续属于书库，不能混入个人学习历史的保留清理。服务器/Mac周期备份保持关闭。

## 统一职责与恢复原则

在packages/core提供可供新前端复用的保存、替换、同步、历史和归档操作；页面负责选择、比较、确认和显示结果。继续使用现有四类学习数据及v3任务，不为历史功能升级整份学习格式。

普通学习仍走轻量本机保存；历史只在适合的保存节点更新，复用内容变更标记。列表读取摘要，用户选中后才读取正文。自动历史保存失败不应阻断普通进度保存，并应明确提示。按用户选择，不另加日初保护点或常驻替换前副本；整份替换失败时通过事务保留原当前数据。

整份替换：解析至暂存 → 严格校验格式、版本与附件引用 → 展示差异 → 确认时刷新并等待有关保存队列 → 复核账号及本机版本 → 同一IndexedDB事务提交当前数据及附件引用 → 更新内存状态 → 更新当日最新历史并标记云端待同步。错误路径必须恢复加载/暂停状态；不接受“失败返回空默认数据”作为成功。提交后不再额外保留另一份日内旧快照；不得误把用户接受的日内历史覆盖扩展成允许失败留下半份当前数据。

恢复以本机为先，离线仍可完成；同步结果另行显示。旧同步基线、回执、待发请求、删除标记和历史保留设置不随学习快照恢复。旧请求回执不确定时保留核对信息，联网确认服务器结果后再构造新上传；不得直接清除未知请求后声称两端一致，也不能重发旧内容盖回恢复结果。

## 已确认的取舍（用户于本次接续中答复）

下面三项替代Pro报告推荐及先前的待定项：

1. **每天只留最新一份。** 用户明确接受当天旧状态不可恢复；不额外实现日初固定点或常驻替换前副本。这里“最新”指该来源成功保存的最新状态，即使是用户确认恢复的较旧学习内容也可成为最新状态，不能偷偷取更大进度。云端默认3个有效日期，本机上限30；本机默认3、选择1–30作为可调整的实现默认值，不将其记成用户单独确认过默认值。
2. **固定北京时间Asia/Shanghai。** 离线中间日期由本机保留，云端按实际收到变更的日期分组，不虚构中间版本，不随设备旅行自动改分组时区。
3. **VS Code客户端可退役。** 用户明确不使用。退役其入口、构建/部署脚本和专属适配，保留Web需要的共享能力、历史数据格式识别及原作者署名。仓库文件删除按用户要求移入废纸篓；不顺带删除未知运行数据或旧学习存档。

其他建议：以“实际业务内容变化且成功提交”产生有效日期，无变化同步、幂等重试、打开页面和删除历史不计日。历史保留策略按来源及所有者隔离，错误未来时间不得挤掉已有日期。列表区分分组日期、保存时间及可核实的数据截至时间，不能把今天保存的旧副本称为今天新进度。

删除建议使用可撤销的最近删除（暂建议24小时），不执行即时不可逆清除。此撤销区仅用于用户主动删除，不为同日每次更新保留旧版本。删除标记独立保存，旧迁移重跑/同步重试/恢复旧学习数据不能使已删除副本复活；当天后续真实变更仍可形成新历史。调小配额先展示影响，附件只在当前数据和全部保留历史均不引用后清理。
