## 第一阶段（本地实现）

- `packages/core/src/learning/planStudyTask.ts`：普通数据输入，明确时间与随机源，输出任务与旧规则下的待清理卡片键；不读取 Pinia、DOM、网络或存储，不修改输入。词条内容引用只读使用。
- `prepareStudyBook.ts`：旧卡片迁移和单元游标整理的显式写操作，以及独立的卡片清理操作。保持原有规则，不趁提取改变“忽略词是否应删除卡片”的产品语义。
- `hooks/dict.ts:getCurrentStudyWord`：旧 UI 适配入口，按原顺序准备、规划、应用清理。它仍有兼容写操作，不能作为只读预览 API。新前端应使用纯规划入口，写操作通过应用层明确调用。
- 本阶段保持持久化格式、同步协议、页面布局、练习模式及任务结果兼容；没有把所有页面变成纯视图，没有宣称完成整体重构。

## 检查入口

在仓库根目录执行：

| 命令 | 行为 |
| --- | --- |
| `pnpm test` / `pnpm test:core` | 核心行为测试 |
| `pnpm test:server` | Go 测试与 vet |
| `pnpm typecheck` | Nuxt 完整类型检查；现有失败不得隐藏 |
| `pnpm build:web` / `pnpm build-web` | 只生成本地 Web 产物，不上传 |
| `pnpm verify` | 依次执行核心、服务端、类型、构建，失败立即返回非零 |
| `pnpm release:eo:web` | 原有 EoPages 发布入口；仅明确授权该发布目标时使用 |

本次验证环境：Node 26.9.0、pnpm 12.5.1、Go 1.27.1。现有 VS Code 与 dev 发布脚本尚未收敛；不要把它们当纯验证入口。自托管正式站点仍使用单独授权的发布流程。

## 后续阶段与验收目标

1. 统一学习范围：无分课词书映射内部默认单元，界面仍叫整本词书；单元内支持整单元或每轮 N 词。
2. 按单元独立保留正式任务，浏览词表不改变学习范围，自由练习不推进正式学习进度；同书 FSRS 共享规则保持明确。
3. 统一本地写入与会话结算，保留失焦同步、CAS 人工冲突处理、幂等请求和账号/标签页隔离。
4. 新数据格式迁移：稳定词书/单元标识，保留词序、阶段、答题位置、统计和卡片；内容未加载不等于进度为零。
5. 更新流程：先完成本机保存，再提示刷新；迁移校验成功后启用新版。服务端拒绝不兼容旧客户端写入。不能靠恢复旧数据库回退。

每次迁移先用数据副本验证，并在正式迁移前重新备份最新本机和云端数据。首阶段备份已保存仓库外，未包含在源码中。支持平台裁剪、Supabase 退役与 UI 重设计另行确定，不混入本阶段。
